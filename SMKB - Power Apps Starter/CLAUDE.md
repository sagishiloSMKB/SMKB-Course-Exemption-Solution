## What this is

A **flow-based (UI-only)** Power Apps Code App starter: Vue 3 + Vite + TypeScript running inside the Power Apps runtime. The app does **not** call Dataverse or any network API directly — all backend work is done by Power Automate flows, called through generated services and a single `unwrap()` boundary. **Hebrew / RTL by default.**

---

## Development Commands

```powershell
pnpm install          # Install deps. No credential needed - design-ui is vendored under vendor/.
pnpm dev              # Dev server — "../generated" barrel is aliased to an in-memory mock automatically
pnpm build            # vue-tsc type check + Vite build → dist/
pnpm lint             # ESLint — bans fetch/XHR/WebSocket & v-html; no stray console.log
pnpm test             # Vitest — runs src/**/*.spec.ts (Node env)
pnpm pa <cmd>         # npm-based Power Apps CLI (e.g. pnpm pa add-flow, pnpm pa push)
powershell -ExecutionPolicy Bypass -File deploy.ps1   # placeholder + env guard + lint + test + build + pnpm pa push
```

## Architecture

### Flow-based data access (UI-only)
Call shape is always: **`generated Service.Run(input)` → `unwrap<T>()` → clean domain type.**
- `src/services/unwrap.ts` — the ONE place that turns a flow `{ success, data, error }` into data (or throws the error code). Don't inline this contract elsewhere.
- `src/services/*Service.ts` — thin domain services. Domain types live **with their service** — there is no shared `src/types/`.
- `src/generated/` — auto-generated by `pnpm pa add-flow`; barrel + one model + one service per flow. **Never edit.** **Committed** (build type-checks against it; CI needs it).
- `.power/schemas/` — generated connector schemas. Also committed.
- ESLint enforces UI-only: `fetch` / `XMLHttpRequest` / `WebSocket` and `v-html` are errors. Never add a direct network call; add or use a flow instead.

### Dev / prod service swap
`vite.config.ts` aliases any bare-barrel import (`from '.../generated'`) to `src/services/mock/generated.ts` **only in `mode === 'development'`**. In build/prod the real `src/generated/` barrel is used. To mock a new flow in dev, add one export to `src/services/mock/generated.ts` — no new file, no new alias. Deep imports (`../generated/models/X`) are not aliased, so type-only imports still resolve to the real files.

### Hash routing
`createWebHashHistory()` (`/#/...`). Required — the Power Apps player intercepts non-hash URLs. Prefer not to rely on client-side role guards for security: identity comes from the runtime (`getContext()`), access is gated by app-sharing, and flows are the real boundary.

### Design system
`@smkbacil/design-ui` registered globally via `app.use(createSmkb())` in `src/main.ts`; components need no per-file import. CSS tokens imported at the top of `main.ts` (uses `tokens-nofonts.css` — the Power Apps asset proxy corrupts web fonts). Reference: `SMKB-UI.md` (auto-generated, do not hand-edit).

### Hebrew / RTL
`index.html` sets `lang="he" dir="rtl"`. Use logical CSS properties (`margin-inline-*`, `inset-inline-*`, `border-inline-*`), `toLocaleDateString('he-IL')`, and `localeCompare(b, 'he')`. Force `dir="ltr"` only on email/phone/ID inputs.

### Config files
- `power.config.json` — PAC config (app ID, environment ID, flow connection references). Populated by `pac code init` + `pnpm pa add-flow`.
- `deploy.config.json` — `targetEnv` (required), `allowedEnvs` (required, ships empty → deploy blocked), `solutionName` (optional).
- `vendor/` — the committed `@smkbacil/design-ui` tarball. The dependency is a `file:` spec, so installs need no credential. Update it with the root `scripts/vendor-design-ui.ps1` (the only step that uses a token).

## First-Time Setup Order

1. `pnpm install` (no credential needed)
2. Delete `power.config.json`, then:
   ```powershell
   pac code init --environment "https://your-org.crm.dynamics.com/" --displayName "Your App Name"
   ```
3. Fill in `deploy.config.json` (`targetEnv`, `allowedEnvs`, optional `solutionName`)
4. `pnpm pa add-flow` for each flow → write domain services (`Service.Run` → `unwrap`) + mock exports
5. Delete the ExampleFlow scaffold (see README → Removing the example)
6. `powershell -ExecutionPolicy Bypass -File deploy.ps1`

`pnpm pa push` updates an existing app record — it does NOT create one. `pac code init` (step 2) is mandatory before the first deploy.

## Optional Solution Assignment

- `solutionName: ""` → deployed standalone (in the environment, not part of a solution).
- `solutionName: "YourSolutionUniqueName"` → `deploy.ps1` passes `--solution-id` so the app is linked to that solution (travels through pipelines).

Change at any time by editing `deploy.config.json` and redeploying. Stage/Production are promoted via Power Platform Pipeline, never `deploy.ps1`.
